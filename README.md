## 사용 데이터 및 조회 범위

### 분석 기간을 적용하는 테이블

**2023년 5월 4일~2024년 5월 5일**의 기록을 각 테이블의 `created_at` 기준으로 조회한다.

```sql
WHERE created_at >= '2023-05-04 00:00:00'
  AND created_at <  '2024-05-06 00:00:00'
```

| 테이블 | 내용 | 추가 조건 |
|---|---|---|
| `polls_questionreport` | 질문 신고 기록 | — |
| `polls_usercandidate` | 질문 카드에 제시된 후보 유저 | — |
| `polls_questionset` | 질문 세트 | `status = 'F'`, `opening_time >= created_at` |
| `polls_questionpiece` | 질문 조각 및 투표·스킵 상태 | — |
| `accounts_userquestionrecord` | 투표 기록 | `answer_status <> 'P'` |
| `accounts_timelinereport` | 타임라인 신고 기록 | — |
| `accounts_blockrecord` | 유저 차단 기록 | — |

### 기간 제한 없이 조회하는 테이블

| 테이블 | 내용 | 조회 조건 |
|---|---|---|
| `polls_question` | 질문 문구 및 생성 정보 | 전체 기간 |
| `accounts_user` | 유저 정보 | `is_superuser = 0`, `is_staff = 0` |
| `accounts_school` | 학교 정보 | 전체 조회 |
| `accounts_group` | 학급과 학교 연결 정보 | 전체 조회 |
| `accounts_attendance` | 유저별 출석 날짜 목록 | 전체 조회 |

- `accounts_user`는 이전 가입자의 활동 기록에도 유저 정보를 연결할 수 있도록 가입일 제한 없이 조회한다.
- `accounts_attendance`는 생성일 컬럼이 없어 전체 조회한다. 출석일 수 분석에서는 날짜 목록을 펼쳐 분석 기간을 적용하고, 동일 유저의 동일 날짜는 중복 제거한다.

## 전처리

### 1. 중복 및 결측 확인

각 테이블에서 다음 항목을 확인한다. 확인 과정에서 행을 자동 삭제하지는 않는다.

- 전체 컬럼이 동일한 중복 행
- 기본키 `id`의 중복
- 기본키 `id`의 결측

### 2. 유사 질문 통합

`QuestionIdMapper`를 사용해 사전에 지정한 동일·유사 질문을 통합한다. 원본 `question_id`는 유지하고, 분석용 `대표 질문 ID`를 추가한다.

| 구분 | 처리 기준 |
|---|---|
| 동일 문구 | 같은 질문으로 통합 |
| 띄어쓰기·문장부호·단순 오타 차이 | 같은 질문으로 통합 |
| 어미·조사·유의어·어순 등의 차이 | 사전에 검토한 질문 목록에 따라 통합 |
| 복제 구간 | ID `3168~4150`과 해당 ID에 `983`을 더한 질문을 같은 묶음으로 처리 |
| 대표 ID | 연결된 질문 묶음에서 가장 작은 ID 사용 |
| 제외 대상 | `vote`, `포인트` 등으로 지정한 질문 ID 제외 |

예를 들어 다음 질문 ID는 하나의 묶음으로 처리한다.

```text
원본 질문 ID: 779, 3967, 4950
대표 질문 ID: 779
```

통합은 자동 유사도 판별이 아닌 사전에 정의한 매핑 규칙을 사용한다.

질문별 신고·투표·읽음 기록은 대표 질문 ID 기준으로 집계한다. 같은 질문 묶음의 행동 기록은 합산하되, 고유 신고자 수는 묶음 전체에서 사용자 중복을 제거해 계산한다.

### 3. 질문 신고 데이터 정리

`df_questionreport_clean`은 원본 신고 기록에 대표 질문 ID를 추가하고, 분석 제외 대상 질문의 기록을 제거한 데이터다.

긍정 사유 제외와 신고 사유 선택은 분석 목적에 따라 별도로 적용한다.

| 분석 | 포함하는 신고 사유 |
|---|---|
| 전체 질문 신고 Top 10 | 긍정 사유만 제외 |
| 질문 신고 사유 분포 | 긍정 사유 포함 |
| 질문 신고자의 성별·학교급 구성 및 차단·숨김 현황 | 질문 내용 관련 사유 7개 |
| 성별·학교급 질문 Top 10, 신고 건수 분포, 선정 질문의 일별 추이 | 질문 내용 관련 사유 7개 |

긍정 사유는 `어떻게 이런 생각을? 이 질문 최고!`다.

질문 내용 관련 사유 7개는 다음과 같다.

| 질문 내용 관련 신고 사유 |
|---|
| 그냥 싫어 |
| 나랑 맞지 않는 질문인 것 같음 |
| 불쾌한 질문 내용 |
| 이 질문은 재미없어요 |
| 기타 |
| 불쾌한 내용이 포함되어 있음 |
| 선정적이거나 자극적인 질문 |

## 주요 집계 기준

| 지표 | 기준 |
|---|---|
| 투표 실행 횟수 | `accounts_userquestionrecord.user_id`별 기록 수 |
| 투표 받은 횟수 | `accounts_userquestionrecord.chosen_user_id`별 기록 수 |
| 읽음 기록 수 | `has_read = 1`인 고유 투표 기록 수 |
| 친구 수 | `friend_id_list`의 중복 ID를 제거한 개수 |
| 출석일 수 | 분석 기간 내 유저별 고유 출석 날짜 수 |
| 질문별 일별 투표 비중 | 해당 질문 투표 수 ÷ 같은 날 전체 투표 수 × 100 |
| 질문당 평균 투표 비중 | 선정한 질문별 일별 투표 비중의 평균 |

- 전체 투표 비중의 분모에서도 mapper 제외 대상을 제거한다.
- 선정 질문의 평균에는 당일 투표 기록이 없는 질문도 0건으로 포함한다.
- 전체 투표가 0건인 날의 투표 비중은 계산하지 않는다.
- 친구 목록의 결측은 0명이 아닌 확인 불가로 처리한다.

## 분석 시 유의사항

- 투표 기록은 확인된 10개 학교에 한정되지만, 신고 기록은 더 넓은 학교 범위를 포함한다.
- 투표 건수와 읽음 기록 수를 전체 노출 횟수로 해석하지 않는다.
- 투표 비중과 신고 비중의 상관관계를 노출 대비 신고율이나 인과관계로 해석하지 않는다.
- 차단은 조회 기간 내 실행 기록, 숨김·친구 목록은 조회 시점에 저장된 상태를 기준으로 한다.
- 관측된 활동 기록이 없는 유저를 실제로 활동하지 않은 유저라고 단정하지 않는다.
